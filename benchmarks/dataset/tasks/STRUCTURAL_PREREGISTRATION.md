# Structural slice: preregistration

Written 2026-10-26, before any agent has answered these questions. Change nothing below after a run starts; record deviations at the bottom.

## Why this exists

The 30-question benchmark is a tie, and its caller/impact group (B) shows no lift. The README previously said the tool "is useful for structural questions"; that was unsupported. This slice tests that claim on questions whose answers are lists of callers, where completeness is checkable and grep must assemble the answer by hand.

## Questions and answer keys

12 tasks in `tasks/structural_tasks.yaml`, generated by `harness/make_structural_tasks.py` (seed 27) at the ERPNext pin `1887825ce5c6fe2fbd5366ab52e4c73de24d23fa`:
- S01-S06: every function that calls target `T` directly.
- S07-S12: direct callers and second-hop callers of `T`.

Keys come from Python `ast` over non-test, non-patch, non-migration `.py` files, matching calls by simple name. A target is eligible only if its name is defined exactly once, never appears in a string literal, and is not in `hooks.py` (so no invisible dynamic dispatch can make a key incomplete). For depth-2 tasks, every direct caller must meet the same conditions. Targets have 3-9 direct callers. 358 targets were eligible; the first 12 after a seeded shuffle were used. The key never uses graphrelay output.

Known limits: name-based matching can attribute a call on an unrelated object that shares a method name (a possible false key entry); dynamic dispatch is excluded by construction, so this slice measures the easy, static case.

## Metrics

Primary: mean key-fact coverage from the existing blind judge (`harness/grade.py`), graphrelay minus baseline, per agent (Sonnet 5.5, GLM 5.3 Flash), 3 repeats, paired bootstrap over the 12 questions (resample questions, average repeats within question).
Secondary: tool calls, input+output tokens and cost per question, turn-cap failures.
LLM-free: `harness/impact_recall.py` (precision/recall of `trace_impact` against the keys).

## Decision rule

- **Supported:** the 95% interval of the coverage difference excludes 0 on **both** agents.
- **Not supported:** otherwise. Then the README, ROADMAP and positioning keep saying "no demonstrated answer-quality advantage", and the structural claim is dropped, not rephrased.
- Cost is reported either way; a coverage gain that costs more per question is stated as such.
- No subgroup or question is dropped after seeing results. 12 questions only detect large effects; a null here is "not shown", not "absent".

## Recorded before running

- `harness/impact_recall.py` first run scored recall 0.87 because it compared function names exactly while graphrelay labels a second same-name symbol in a file `name#2`. The scorer was changed to strip that suffix (after seeing that run). Final: recall 1.00, precision 0.91.
- The 12 tasks were not reviewed by hand beyond spot-checking S05 against `grep` (3 callers, all matched).

## Deviations

See the final "Deviations" section at the end of this file (the list is appended there as they occur).

# Addendum: Gitea slice (2026-10-27)

Second repository for the same question shape, chosen because Go is statically typed and a compiler-checked key is possible. Same metrics and **same decision rule** as above; nothing in the rule was changed after seeing Gitea results.

- **Target:** `go-gitea/gitea` at `f35c67bd79b3bff9c28eb8171d53586cc800bd5c` (shallow clone in `benchmarks/dataset/repos/gitea`, git-ignored), Go 1.27.3, about 347k non-test Go lines in 3,168 files.
- **Keys:** `harness/gokeys` (Go, `golang.org/x/tools/go/packages`) emits a type-checked static call graph; `harness/make_structural_tasks_go.py` (seed 27) turns it into `tasks/structural_gitea_tasks.yaml`: 6 direct-caller and 6 two-hop tasks. The keys never use GraphRelay output.
- **Eligibility:** plain function (no receiver, not generic), never used as a function value (so registered route handlers are excluded), not called from a package-level initialiser, unique bare name, 3-9 distinct callers. Depth-2 tasks need every direct caller to meet the same rule. A textual cross-check must agree: the count of `name(` occurrences in non-test `.go` files (minus the definition) equals the type checker's call-site count. 1,082 targets were eligible.
- **Known limits:** packages were loaded with default build tags only, so callers under other tags are invisible to the checker (the textual cross-check removes most such targets); calls through interfaces and function values are excluded by construction, so this again measures the easy, static case.
- **Free metric result (2026-10-27, same `gr` build as the ERPNext check):** `impact_recall.py --tasks tasks/structural_gitea_tasks.yaml`: **recall 1.00, precision 0.755** (micro). All 26 extra results were callers in `_test.go` files, which GraphRelay indexes and the key excludes by rule; excluding test files precision would be 1.00 (raw figure is the one reported).
- **Not yet run:** the agent slice on Gitea (`run-sot.sh` is hard-wired to ERPNext and needs a `--repo` option first).

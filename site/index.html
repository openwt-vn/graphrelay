Code search that follows the call graph.

GraphRelay indexes a repository into a symbol and call graph, then lets a coding agent ask for relevant code, a symbol's callers and callees, and the blast radius of a change. One Rust binary. Your code stays on your machine.

01 The design

Local, private, and built on a call graph.

A single binary watches your repository, parses it with tree-sitter, and keeps a symbol and call graph in SQLite. Agents reach it over MCP; you can browse the same graph in the web UI.

LOCAL

Your code stays on your machine

No cloud account, no API key, no embedding model to download. Every retrieval stage is a local SQLite query or an in-memory graph walk.

ONE PORT

MCP, REST and a web UI on :3030

One Rust binary, gr. No Python, no Node, no database server. The web UI shows an interactive call graph and an inspector for any symbol.

CALL GRAPH

Callers, callees, blast radius

Ask for relevant code, for the callers and callees of a symbol, or for what a change would reach. The graph is built from the code itself, with no model in between.

02 How retrieval works

Four stages, one ranked list.

  1. 01

    lexical_search

    SQLite FTS5 with BM25 finds the top candidate symbols, with camelCase/snake_case decomposition, stemming and synonym expansion.

  2. 02

    expand_graph

    Adds the callers and callees of those hits, one hop out, with a decayed score.

  3. 03

    personalized_pagerank

    A query-seeded PageRank over the graph gives each candidate a centrality score.

  4. 04

    rerank

    Graph score and BM25 are combined into a single ranked list, with the source snippet attached.

No embedding model, no vector index, no cloud call. The tradeoff: a query needs real vocabulary overlap with the code to find it.

03 MCP tools

Exactly four tools.

A small surface on purpose. Any MCP client can call them at POST http://localhost:3030/{project}/mcp.

search_code

(intent? | implements?, top_n?)

Fused lexical and graph retrieval. Pass intent for a natural-language search, or implements to find everything implementing a named interface, trait or base class.

inspect

(symbol? | path?, include_source?)

A symbol's definition, callers, callees and docstring; or, for a path, the file's context or a module summary.

trace_impact

(symbol, depth?)

The blast radius of a change: what breaks if this symbol changes, from the callers in the call graph.

watch_status

()

Index freshness, so an agent can tell when results may be stale.

04 Honest status

We measure. Here is what we found.

Our own agent benchmark: Claude Sonnet 5.5 answers 30 hard questions about ERPNext, 3 repeats per arm, and a blind judge scores key-fact coverage. The control is the same agent with only Grep, Read and Glob.

Result: no reliable advantage over the Grep/Read/Glob baseline. GraphRelay scored 71.2% against 70.6%, a difference of +0.6 points whose 95% interval runs from −4.0 to +5.0.

05 Install

One installer, then three commands.

shell 
$ curl -fsSL https://raw.githubusercontent.com/openwt-vn/graphrelay/main/scripts/install.sh | sh$ cd /path/to/your-project$ gr init    # register the project$ gr start   # start the daemon and index$ gr setup   # wire up Claude Code, Cursor, OpenCode, Amp or Codex
